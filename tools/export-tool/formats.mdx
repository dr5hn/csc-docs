You choose one format per export. The format cost is added once, whatever the number of datasets.

## Format costs

| Format | Extra credits | File content |
|:-------|:-------------:|:-------------|
| JSON | +2 | One array of objects per dataset |
| NDJSON | +2 | One JSON object per line |
| XML | +2 | One XML file per dataset |
| YAML | +2 | One `.yml` file per dataset |
| CSV | +3 | One CSV file per dataset |
| Markdown | +3 | One `.md` table per dataset |
| MongoDB | +3 | One Extended JSON `.json` file per dataset |
| SQL | +4 | One generic `INSERT` script, `export.sql` |
| Excel | +4 | One `workbook.xlsx` with a sheet per dataset |
| GeoJSON | +4 | One `.geojson` file per dataset |
| PostgreSQL | +5 | One `export.sql` for PostgreSQL |
| SQL Server | +5 | One `export.sql` for SQL Server |
| SQLite3 | +5 | One `export.sql` for SQLite |

The preview shows the exact total, including extras that depend on your selection. Check the preview before you confirm, because the preview is the price you pay.

## What's in the download

Exports of the current data snapshot always arrive as a ZIP file. The file is generated while you download it, so allow time for preparation and check your browser’s Downloads for progress. You do not need to buy the export again if a download fails.

| Format | Files inside the ZIP |
|:-------|:---------------------|
| JSON, NDJSON, XML, CSV, GeoJSON | `countries.json`, `states.json` and so on, one file per selected dataset, using the format's own extension |
| YAML | `<dataset>.yml` |
| Markdown | `<dataset>.md` |
| MongoDB | `<dataset>.json` |
| Excel | `workbook.xlsx` |
| SQL, PostgreSQL, SQL Server, SQLite3 | `export.sql` |

Every ZIP of the current snapshot also contains:

- `source-manifest.json`, which records the snapshot the data came from.
- The source notices and migration notes that belong to that snapshot.
- A `flags/` folder with `png` and `svg` flags, only when you added the flag bundle.

The ZIP is named `csc-<format>-history-<date>.zip`.

<Note>
Older exports made before this snapshot system keep their original shape. A legacy Excel export without the flag bundle downloads as a plain `.xlsx` file. A legacy export with the flag bundle downloads as a ZIP.
</Note>

## Read the files

List and read an export:

```bash
unzip -l csc-json-history-2026-11-24.zip
unzip -p csc-json-history-2026-11-24.zip source-manifest.json
```

Read postcodes without losing leading zeros. The `code` field is always text.

```python
import json, zipfile

with zipfile.ZipFile("csc-json-history-2026-11-24.zip") as z:
    postcodes = json.loads(z.read("postcodes.json"))

print(postcodes[0]["code"])  # a string, for example "01234"
```

Import a SQL export:

```bash
unzip csc-postgresql-history-2026-11-24.zip -d export
psql "$DATABASE_URL" -f export/export.sql
```

<Tip>
Choose the dialect that matches your database. The generic SQL format writes plain `INSERT` statements. PostgreSQL, SQL Server and SQLite3 write statements for that dialect.
</Tip>

## Data shape to expect

- **Counties.** Most counties have a primary `state_id`. Multi-state counties preserve their state links in the `states` column. Seven New Zealand counties have no primary state, so their `state_id` and `state_code` are `null`, and the links are only in `states`.
- **Cities.** Three Western Sahara (EH) cities have no state, so their `state_id` and `state_code` are `null`. Cities can link to a county with `county_id`.
- **Postcodes.** `code` is a string, because leading zeros matter. A postcode always links to a country. The links to a state and to a city are optional. Postcodes do not link to counties. The same code can appear more than once.
- **Null values.** Missing relationships and source values can be `null` or absent; formats without a null type use an empty cell. Check each column on [`/api/datasets`](https://eapi.countrystatecity.in/api/datasets), which lists the columns and the nullable ones.

<Warning>
Source coverage varies by country and by dataset, and postcodes have a `source` column you can select. There is no guarantee of complete postal coverage worldwide. Read the notices in your ZIP for the source terms.
</Warning>

## Which format should you choose?

| You want to | Use |
|:------------|:----|
| Load data into a web or mobile app | JSON |
| Process a large file line by line | NDJSON |
| Open it in a spreadsheet | Excel or CSV |
| Create tables in a database | SQL, PostgreSQL, SQL Server or SQLite3 |
| Draw points on a map | GeoJSON |
| Load into MongoDB | MongoDB |
| Share a readable table in a document | Markdown |
